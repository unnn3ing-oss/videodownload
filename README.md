# YouTube 批量下載器

Chrome 擴充功能加本機小程式，用來把**公司 YouTube 頻道的公開影片**批量下載到自己的電腦（720p 或 1080p），檔名直接使用影片標題。下載走你自己電腦的網路，不經過雲端。操作介面有兩個，看到的是同一份清單：Chrome 的**側邊面板**，以及放在 GitHub Pages 的**網頁版**。

> **使用前請先確認**：YouTube 條款原則上不允許用官方功能以外的方式下載；影片裡的音樂與外部素材，授權範圍可能只限 YouTube。請先取得頻道管理部門同意，轉發到其他平台前也請確認授權。如果管理部門能直接提供成品原檔，畫質會比從 YouTube 抓下來的更好。

## 限制（先看這裡）

- 不使用登入 cookies，只能下載公開影片與「不公開連結」影片；私人、會員專屬、年齡限制影片會失敗並顯示原因。
- 這個工具在開發環境**只驗證了邏輯與擴充功能介面**（含假的下載引擎）。**真實下載 YouTube、安裝檔在真實 Windows／Mac 上的行為，尚未驗證**，請依下面的「冒煙測試」跑一次。
- 只支援 Chrome 114 以上（電腦版）、Windows 與 Mac。網頁版同樣需要 Chrome。
- 網頁版只是遙控器：沒有裝擴充功能和本機小程式，網頁什麼都下載不了，只會引導你完成部署。

## 安裝

最快的方式是打開**網頁版**（`https://unnn3ing-oss.github.io/videodownload/`），左邊的「設定流程」會一步步帶你做，完成一步就自動打勾：部署擴充功能 → 在 Chrome 載入 → 部署本機小程式 → 自動連線，過程中不需要重新整理頁面。也可以照下面的手動步驟。

### 1. 載入擴充功能（Windows、Mac 相同）

1. 下載 [main.zip](https://github.com/unnn3ing-oss/videodownload/archive/refs/heads/main.zip)（最新發佈版），解壓縮到一個**固定、之後不會搬動**的位置，裡面有 `extension` 資料夾。
2. Chrome 開啟 `chrome://extensions`，右上角打開「開發人員模式」。
3. 按「載入未封裝項目」，選擇 `extension` 資料夾。
4. 把擴充功能釘選到工具列。之後點工具列上的圖示，就會在視窗右側開啟**側邊面板**，切換分頁也不會消失。（Chrome 啟動時可能提示「停用開發人員模式擴充功能」，請選保留。）

### 2. 下載部署（只需做一次）

點工具列的擴充功能圖示打開側邊面板，按**「下載部署」**，會依你的系統取得對應的安裝檔。

**Windows**
1. 到下載資料夾雙擊 `install-windows.cmd`。
2. 若出現 SmartScreen「Windows 已保護您的電腦」，按「其他資訊」→「仍要執行」。
3. 視窗會下載並安裝需要的元件（Python、yt-dlp、Deno、ffmpeg），最後顯示「安裝完成」。

**Mac**
1. 解壓縮下載到的 `install-mac.zip`。
2. 對 `install-mac.command` 按**右鍵 →「打開」**（直接雙擊會被 Gatekeeper 擋下）。若 macOS 15 以上仍被擋、只出現「無法打開」，請到「系統設定 → 隱私權與安全性」，往下找到這個檔案並按**「強制打開」**；或改用終端機（不會經過 Gatekeeper）：輸入 `bash `（後面有一個空格），把 `install-mac.command` 拖進視窗，按 Enter。
3. 需要系統有 `python3`（3.9 以上）。沒有的話，安裝檔會提示先在終端機執行 `xcode-select --install`。

### 3. 啟動

回到 Chrome。側邊面板與網頁版打開時都會自動連線本機小程式；沒有反應時按**「啟動」**。狀態顯示「已啟動」就可以使用。

## 更新

擴充功能會每 6 小時自動檢查一次是否有新版本；有的話，工具列圖示會出現「新」，面板標題旁會出現「有新版本」。

1. 打開側邊面板，展開下方的**「設定與工具」→「版本與更新」**（點標題旁的「有新版本」會直接跳到這裡）。也可以隨時按「檢查更新」手動檢查。
2. 先按「啟動」（更新本機小程式需要它連著），下載進行中時不能更新，等下載結束再按。
3. 按**「更新到最新版」**。**第一次**按鈕會寫「選擇擴充功能資料夾並更新」：請選到你當初載入的那個 `extension` 資料夾（Chrome 不允許選磁碟根目錄，也不允許選「下載」「文件」等系統資料夾本身，請選 `extension` 這一層）。選好後 Chrome 會記住，之後不用再選。
4. 每個檔案都會和 GitHub 上登錄的雜湊值逐一比對，全部吻合才會寫入；本機小程式也會先備份舊版、更新後自我檢查，失敗會自動還原。
5. 更新完成後擴充功能會自動重新載入，**再按一次「啟動」**即可。

## 使用

1. **增加影片**：在輸入框貼上 YouTube 網址，按「增加」（或 Enter）。清單會多一欄，先出現骨架動畫，隨後帶入**影片標題、封面、片長**。可一次貼多個網址；貼播放清單或頻道網址會展開成多欄（最多展開幾支可在「設定」調整，預設 50）。目前分頁是 YouTube 時，側邊面板的「目前分頁」卡片按「加入」即可。
2. **整理清單**：每一欄最右邊的 **X** 可以從清單移除。下載失敗的欄位有「重試」。清單上限 500 欄。
3. **重複影片**：清單裡影片 ID 或標題相同的影片，後加入的那一欄會標示「**重複下載**」、暫停且不會下載，避免同名檔案互相覆蓋；刪掉先加入的那一欄，它就會恢復正常。
4. **選解析度和間隔**：720p 或 1080p（網頁版在輸入框與「增加」之間，側邊面板在「設定」裡；選 1080p 但影片只有 720p 時會下載 720p，不算失敗）；「每支間隔」是每支影片下載完之後的冷卻秒數（3–60，預設 10）。
5. **開始全部下載**：依加入順序（最早到最晚）一支一支下載，每支之間冷卻，進度、速度與剩餘時間直接顯示在該欄；冷卻中的下一欄會顯示「N 秒後開始」。下載途中新增的影片會自動接在後面。關掉面板或網頁不會中斷下載（關閉 Chrome 才會中止，重跑時會從中斷處續傳、跳過已完成的影片）。
6. **複製內文**：每一欄的複製按鈕，會複製 `【影片標題】` 加說明欄前三個 hashtag（例如兩行：`【標題】` 與 `#標籤一 #標籤二 #標籤三`）。說明欄第一次才去抓，要等幾秒；沒有 hashtag 時只複製標題。
7. **下載封面**：滑鼠移到封面上，縮圖會反灰並出現下載符號，按一下即下載該影片**原尺寸**的封面（依序嘗試 maxres、720p、sd、hq 尺寸，用第一個存在的，舊影片可能只有較小的圖）。本機小程式連線時，圖存到**影片的存放資料夾**，檔名是標題前六個字（不計標點與空白），例如「颱風假放不放.jpg」，同名時加 `_2`；只有擴充功能、小程式沒連線時，會改存到瀏覽器的「下載」資料夾。
8. 影片預設放在「下載」資料夾下的 `YT下載`，可在「設定與工具」修改。
9. 如果顯示「下載引擎可能過舊」，按**「更新下載引擎」**。YouTube 常改版，引擎需要定期更新。（Mac 上這個按鈕會重新下載官方的 yt-dlp 並核對校驗碼，因為免解壓縮版不能自己更新。）

影片檔名規則：Windows 不允許的字元會換成 `_`；太長的標題會截短；已有同名但不同影片時，檔名後面加上 ` [影片ID]`。

## 冒煙測試（請在你自己的電腦做一次）

1. 安裝並啟動，確認狀態顯示「已啟動」，並顯示 yt-dlp 版本、沒有「找不到 ffmpeg」「找不到 JS 執行環境」的警告。
2. 貼一支**公開的短影片**按「增加」，確認出現標題和封面；選 720p，按開始下載。確認檔案出現、檔名是影片標題、可以播放。
3. 貼**兩三支公開影片**（含一個小的播放清單），確認依順序下載、每支之間有冷卻倒數、各自的欄位裡有進度。
4. 再貼同一支影片，確認顯示「重複下載」且不會下載。
5. 按「複製內文」，貼到記事本確認格式；把滑鼠移到封面按一下，確認影片資料夾出現「標題前六字.jpg」。
6. 再按一次下載，確認顯示「已下載過，略過」。貼一支私人或已刪除的影片，確認顯示明確的失敗原因，且不影響其他影片。
7. 「下載部署」的下載動作若沒有反應，請回報（程式已有備援方式，但尚未在真實 Chrome 驗證）。

**尚未在真實環境驗證的部分**：真實 YouTube 的下載與冷卻、說明欄 hashtag 是否完整、各影片實際有哪種封面尺寸；網頁版在擴充功能剛安裝後免重新整理即偵測到（擴充功能重新載入後的行為在自動測試環境無法驗證）、GitHub Pages 實際網址與資料夾選擇器的限制。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 狀態顯示「尚未部署」 | 先按「下載部署」並執行安裝檔，完成後再按「啟動」 |
| 狀態顯示「Chrome 拒絕連線」 | 擴充功能識別碼與安裝檔不符，請重新按「下載部署」並再執行一次安裝檔 |
| 顯示「找不到 JS 執行環境」或「引擎過舊」 | 重新執行安裝檔，或按「更新下載引擎」 |
| Mac 上出現「Python.framework 已損毀，無法打開」，或下載失敗訊息含 `Failed to load Python shared library … _MEI…` | 這是舊版安裝檔裝的單檔版 yt-dlp：每次執行都把自己解壓縮到暫存資料夾，而 Chrome 啟動的程式寫出的檔案會被 macOS 標成「從網路下載」而擋下。請把擴充功能更新到最新版（0.2.2 以上）後重新執行安裝檔，或在面板按「更新下載引擎」，兩者都會改裝免解壓縮版。警告視窗請按「取消」，不要按「丟到垃圾桶」 |
| 顯示「YouTube 要求登入或驗證」 | 這是 YouTube 對該網路的限制。請改用住宅或公司網路，不要用雲端或 VPN |
| Windows 安裝時 yt-dlp 無法執行 | 可能缺少 Visual C++ 執行階段，或被防毒軟體攔截 |
| 公司電腦無法安裝 | IT 可能限制了開發人員模式擴充功能、腳本執行或 Native Messaging，需請 IT 協助 |
| 更新後本機小程式無法啟動 | 把 `<安裝目錄>/backup/host/` 裡的檔案複製回 `<安裝目錄>/host/`（只保留上一版的備份）。不要重新執行安裝檔：安裝檔隨擴充功能一起更新，會裝回同一份有問題的版本；要退回舊版請改用上一版的 main.zip |
| 檢查更新顯示「GitHub 暫時限制查詢次數」 | 同一個網路一小時內查詢太多次，稍後再試即可 |
| 檢查更新顯示「GitHub 拒絕了查詢（HTTP 403）」 | 公司網路的代理或防火牆擋下了 api.github.com，請 IT 放行 `api.github.com` 與 `raw.githubusercontent.com` |
| 檢查更新顯示「尚未發佈：找不到 main 分支」 | 維護者還沒把程式碼併入 `main` |
| 更新時顯示「這個資料夾不是目前載入的擴充功能資料夾」 | 你可能解壓縮了多份。到 `chrome://extensions` 找到這個擴充功能，看「載入位置」，再選那個資料夾（面板已自動忘記先前選的資料夾） |
| 網頁版一直顯示「還沒偵測到擴充功能」 | 先完成步驟 1、2 並確認擴充功能已啟用；剛裝好時網頁通常會自己偵測到，若 10 秒後仍沒有，重新整理網頁；擴充功能被重新載入後也請重新整理網頁 |
| 網頁版顯示「與擴充功能的連線中斷」 | 擴充功能被停用、重新載入或移除了。到 `chrome://extensions` 確認它已啟用；恢復後網頁會自己解鎖，不行再重新整理。連線中斷期間新增與清單都是鎖住的 |
| 網頁版顯示「與本機小程式的連線中斷」 | 小程式被關掉了，網頁會自動嘗試重新連線；如果顯示「啟動後馬上又關閉了」，代表自動重試 5 次都失敗，確認已執行過安裝檔，再按步驟 4 的「啟動」重試 |
| 顯示「本機小程式的版本太舊」，「開始全部下載」按不了 | 本機小程式比擴充功能舊。到側邊面板的「版本與更新」按「更新」，完成後會自動重新連線 |
| 按「下載安裝檔」後 Chrome 的下載記錄顯示失敗（檢查網際網路連線） | 這是舊版擴充功能的問題，已修正（把擴充功能更新到最新版即可）。如果仍然失敗，網頁會顯示 Chrome 回報的原因；若顯示「找不到安裝檔」，代表部署出來的資料夾缺檔，請回步驟 1 重新部署 |
| 封面存到「下載」資料夾，不在影片旁邊 | 本機小程式當時沒連線，或還是舊版；連線並更新本機小程式後，再按一次封面即可 |
| 封面顯示「找不到封面圖片」 | 這支影片沒有任何尺寸的公開封面圖片，或暫時連不上 YouTube 圖片伺服器 |
| 清單裡有一欄顯示「重複下載」 | 清單裡已有影片 ID 或標題相同的影片，這一欄不會下載；不需要的話按 X 移除 |
| 選擇資料夾時被 Chrome 拒絕 | 不要選磁碟根目錄或「下載」「文件」「桌面」資料夾本身，請選擴充功能所在的 `extension` 那一層 |

## 維護者：發版

更新會追蹤 GitHub 上的 `main` 分支（與圖片套版產生器相同）。修改都先記錄在功能分支，不會影響同事；確認沒問題、併入 `main` 後，同事才會收到更新。每次要發版時：

1. 同步更新 `extension/manifest.json` 的 `version` 與 `host/version.py` 的 `VERSION`，兩者必須相同（測試強制）；**不要動 `manifest.json` 的 `key`**，否則擴充功能識別碼改變，更新會被拒絕。
2. 跑完測試：`python -m pytest`，並執行 `python build.py` 重新產生安裝檔、把 `extension/installers/` 一併提交。
3. 確定可以發佈後，把功能分支併入 `main`（在 GitHub 開 Pull Request 並合併，或 `git push origin <commit>:main`）。
4. 同事的擴充功能最多 6 小時內會發現新版本（或按「檢查更新」立即檢查）。

**網頁版**放在 GitHub Pages：到 repo 的 Settings → Pages，來源選 `main` 分支、根目錄（只需設定一次）。網址是 `https://unnn3ing-oss.github.io/videodownload/`；網頁與擴充功能只認這個網址，改了網址要同步改 `extension/lib/constants.js` 的 `WEB_ORIGIN`、`WEB_PATH` 與 `manifest.json`。

**安全提醒**：這套更新沒有數位簽章，信任來源就是 `main` 分支本身；能推送到該分支的人，就能影響所有同事的電腦。請對 `main` 分支開啟 GitHub 分支保護（限制誰能推送），並對所有有推送權限的 GitHub 帳號啟用雙重驗證。

## 開發

```bash
pip install -r requirements-dev.txt
python -m pytest                          # host 與建置腳本測試
node --test extension/tests/*.test.mjs    # 擴充功能純邏輯測試（含下載安裝檔、連線提示與自動連線）
npm i --no-save playwright-core@1.56.1    # e2e 需要（Chromium 位置可用 PW_CHROMIUM 指定）
node extension/tests/e2e/update.e2e.mjs     # 自我更新的端對端測試（假 GitHub、假資料夾）；環境變數同上
node extension/tests/e2e/queue.e2e.mjs      # 背景程式的清單（增加、重複、依序下載與冷卻、複製內文、封面、網頁來源限制）
node extension/tests/e2e/web.e2e.mjs        # 網頁版（以 route 模擬 GitHub Pages）：沒有擴充功能時的部署、自動偵測與連線、與側邊面板同一份清單
node extension/tests/e2e/oldhost.e2e.mjs    # 連到舊版（0.1.0）本機小程式時：兩個畫面的提示、停用開始、複製內文的說明
node extension/tests/e2e/sidepanel.e2e.mjs  # 無頭 Chromium 端對端測試（假引擎）；結束碼 2 代表無法啟動瀏覽器；設 E2E_SHOTS=資料夾 會順便截圖，E2E_SCHEME=dark 測深色模式
node tools/make-icons.mjs                 # 改了 extension/icons/icon.svg（網頁版與擴充功能共用的圖示）後，重新產生 PNG 圖示
python build.py                           # 修改 host 程式碼後重新產生安裝檔，並提交 extension/installers/
```

- `host/`：Native Messaging 小程式（只用 Python 標準函式庫）。
- `extension/`：Chrome 擴充功能（Manifest V3）；`lib/queue.js` 是清單的純函式，`lib/queue-controller.js` 負責與本機小程式往來，`bridge.js` 是網頁版的內容腳本。
- `index.html`、`web/`：網頁版（GitHub Pages），共用 `extension/lib/` 的清單繪製與部署程式。
- `build.py`、`installers/templates/`：產生單檔安裝檔，內嵌 host 程式碼。測試會檢查已提交的安裝檔與最新程式碼一致。
- `docs/superpowers/`：設計文件與實作計畫。
