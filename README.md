# YouTube 批量下載器

Chrome 擴充功能加下載助手，用來把**公司 YouTube 頻道的公開影片**批量下載到自己的電腦（720p 或 1080p），檔名直接使用影片標題。下載走你自己電腦的網路，不經過雲端。操作介面有兩個，看到的是同一份清單：Chrome 的**側邊面板**，以及放在 GitHub Pages 的**網頁版**。

> **使用前請先確認**：YouTube 條款原則上不允許用官方功能以外的方式下載；影片裡的音樂與外部素材，授權範圍可能只限 YouTube。請先取得頻道管理部門同意，轉發到其他平台前也請確認授權。如果管理部門能直接提供成品原檔，畫質會比從 YouTube 抓下來的更好。

## 限制（先看這裡）

- 不使用登入 cookies，只能下載公開影片與「不公開連結」影片；私人、會員專屬、年齡限制影片會失敗並顯示原因。
- 這個工具在開發環境**只驗證了邏輯與擴充功能介面**（含假的下載引擎）。**真實下載 YouTube、安裝檔在真實 Windows／Mac 上的行為，尚未驗證**，請依下面的「冒煙測試」跑一次。
- 只支援 Chrome 114 以上（電腦版）、Windows 與 Mac。網頁版同樣需要 Chrome。
- 網頁版只是遙控器：沒有裝擴充功能和下載助手，網頁什麼都下載不了，只會引導你完成部署。

## 安裝

**一個安裝檔搞定**（Windows、Mac 都是）：打開**網頁版**（`https://unnn3ing-oss.github.io/videodownload/`），還沒安裝時會整頁蓋上**安裝引導視窗**（「安裝 YT批量下載器」），上方是四個步驟的圓圈進度列（只有目前這一步顯示名稱），每一步有一張小動畫示範圖，用「上一步／下一步」前進（也可以直接點進度列）：**下載安裝檔 → 執行安裝檔 → 載入擴充功能 → 完成**。網頁偵測得到的步驟會自動打勾，視窗也會自己跳到下一個該做的步驟，不用重新整理。全部完成、確認能下載後，視窗會**自動關閉**，並記住「已經設定好」。

### 安裝檔做什麼

只要在電腦上**授權執行一次**，它會自己做完：

1. **跳出視窗讓你選資料夾**，擴充功能會放在裡面新建的 `YT批量下載器` 資料夾（取消就放在使用者資料夾）。已經有同名資料夾而且放著別的東西時會拒絕並說明；那個資料夾本來就是這個擴充功能的，就直接更新。
2. 下載並檢查需要的元件（yt-dlp、Deno、ffmpeg；Windows 另外有內嵌的 Python）。每一項都先印出它的用途，再用「真的能不能執行」判斷：能用的略過，壞掉或缺少的才下載，下載完會再試跑一次。ffmpeg 一律放自己的一份（Mac 依晶片下載原生版，Apple Silicon 不需要 Rosetta），不會連到別處的副本，所以之後解除安裝 Homebrew 的 ffmpeg 也不受影響；舊安裝留下的連結會被換掉。
3. 向 Chrome 登錄下載助手，並**測試**：用 Chrome 啟動它的方式啟動一次，確認它回應、能執行 yt-dlp。
4. 列出每一項的檢查結果，最後打開 Chrome 的「擴充功能」頁和那個資料夾。

你最後只剩一件事（只做一次）：在 Chrome 的擴充功能頁打開右上角「開發人員模式」，按「載入未封裝項目」，選 `YT批量下載器` 資料夾（網頁版步驟 3 有「複製名稱」按鈕）。載入後網頁會自動偵測並連線。

**Windows**：網頁版步驟 1 按「下載 Windows 安裝檔」，到下載資料夾雙擊 `install-windows.cmd`。若 Chrome 說檔案可能有害，按「保留」；若出現 SmartScreen「Windows 已保護您的電腦」，按「其他資訊」→「仍要執行」。

**Mac（建議：一行指令，不用下載）**：網頁版步驟 1 按「複製安裝指令」，打開「終端機」（Cmd+空白鍵，輸入「終端機」），貼上，按 Enter。指令是 `curl -fsSL https://raw.githubusercontent.com/unnn3ing-oss/videodownload/main/extension/installers/install-mac.sh | bash`。不會經過 Chrome 下載，所以沒有 macOS 的「無法打開」提示。需要系統有 `python3`（3.9 以上），沒有的話安裝程式會提示先執行 `xcode-select --install`。

**Mac（備用：下載安裝檔）**：解壓縮 `install-mac.zip`，對 `install-mac.command` 按**右鍵 →「打開」**。若 macOS 15 以上仍被擋，到「系統設定 → 隱私權與安全性」按「強制打開」；或在終端機輸入 `bash `（後面有空格），把檔案拖進視窗，按 Enter。

網頁版提供的安裝檔永遠是 `main` 分支的最新版（連結直接指向網頁自己的資料夾），所以不用擔心拿到舊的。

### 安裝檔就是修復工具

日後遇到任何問題（連不上、下載失敗、被防毒或系統擋下），**重新執行同一個安裝檔**即可：它沿用上次的擴充功能資料夾、不會再問，逐項確認每個元件，壞掉的才重新下載（Mac 還會移除「從網路下載」的標記），最後列出每一項：

```
  ✔ Python 3.13.2
  ✔ 下載引擎 yt-dlp 2026.08.19
  ✘ 找不到 ffmpeg（合併影片與聲音需要）
      → 重新執行安裝檔（它會自動檢查並修復）
```

有 ✘ 時安裝檔不會說「安裝完成」，並告訴你下一步。下載助手已經在跑的時候，也可以在側邊面板「設定與工具」或網頁版左側按**「檢查環境」**看同一份報告，並用**「嘗試自動修復」**處理安全的項目。命令列：`python3 host/doctor.py --home <安裝目錄>`。

### 安裝檔為什麼以後不用改

安裝檔本身只是一個起手式（確認有 Python、解開裡面附的檔案、執行 `host/installer.py`）。下載位址、要裝哪些元件、檢查項目都在 `host/installer.py`，它和下載助手一起更新；擴充功能的新功能則走下面的「更新」。所以新版本只要更新到網頁版與擴充功能，安裝檔不必重新發給同事。

### 不用安裝檔放擴充功能（進階）

網頁版步驟 3 底下的「沒有用安裝檔放擴充功能？自己部署」：自己建一個資料夾（名稱 `YT批量下載器`），按「選擇資料夾並寫入」，或下載 ZIP 解壓縮，再到 `chrome://extensions` 載入。這樣的話**下載助手仍要用安裝檔安裝**，而且網頁版的更新按鈕不知道資料夾在哪，要改用側邊面板的更新（第一次選一次資料夾）。

### 啟動

回到 Chrome。側邊面板與網頁版打開時都會自動連線下載助手；沒有反應時按**「啟動」**。狀態顯示「已啟動」就可以使用。

## 更新

只按一個鍵：**「檢查更新」**。網頁版左側的「版本與更新」，以及側邊面板「設定與工具」裡的「版本與更新」都有。網頁版連線後會自動檢查一次；擴充功能也每 6 小時檢查一次，有新版本時工具列圖示出現「新」。

1. 按「檢查更新」，會顯示目前版本（擴充功能與下載助手）和 GitHub 上的最新版本。
2. 有新版本時按**「更新到最新版」**。每個檔案都會和 GitHub 上登錄的雜湊值逐一比對，全部吻合才寫入；先更新下載助手（會備份舊版、更新後自我檢查，失敗自動還原），再由下載助手把擴充功能的新檔案寫進安裝檔記錄的資料夾（寫入失敗會還原），**不需要再選資料夾**。最後擴充功能自動重新載入，網頁會等它回來並確認版本。
3. 下載進行中不能更新，等下載結束；更新要下載助手連著。
4. 如果擴充功能不是用安裝檔放的（下載助手不知道資料夾在哪），網頁版會請你改用側邊面板的更新：第一次按鈕會寫「選擇擴充功能資料夾並更新」，選你載入的那個資料夾（Chrome 不允許選磁碟根目錄或「下載」「文件」等系統資料夾本身），之後 Chrome 會記住。

只有「安裝檔本身」的內容（極少）改了才需要重新執行安裝檔；平常不需要。

## 使用

1. **增加影片**：在輸入框貼上 YouTube 網址，按「增加」（或 Enter）。清單會多一欄，先出現骨架動畫，隨後帶入**影片標題、封面、片長**。可一次貼多個網址；貼播放清單或頻道網址會展開成多欄（最多展開幾支可在「設定」調整，預設 50）。目前分頁是 YouTube 時，側邊面板的「目前分頁」卡片按「加入」即可。
2. **整理清單**：每一欄最右邊的 **X** 可以從清單移除。下載失敗的欄位有「重試」。清單上限 500 欄。
3. **重複影片**：清單裡影片 ID 或標題相同的影片，後加入的那一欄會標示「**重複下載**」、暫停且不會下載，避免同名檔案互相覆蓋；刪掉先加入的那一欄，它就會恢復正常。
4. **選解析度和間隔**：720p 或 1080p（網頁版在輸入框與「增加」之間，側邊面板在輸入框下方、「增加」按鈕旁；選 1080p 但影片只有 720p 時會下載 720p，不算失敗）；「每支間隔」是每支影片下載完之後的冷卻秒數（3–60，預設 10）。
5. **開始全部下載**：依加入順序（最早到最晚）一支一支下載，每支之間冷卻，進度、速度與剩餘時間直接顯示在該欄；冷卻中的下一欄會顯示「N 秒後開始」。下載途中新增的影片會自動接在後面。關掉面板或網頁不會中斷下載（關閉 Chrome 才會中止，重跑時會從中斷處續傳、跳過已完成的影片）。
6. **複製內文**：每一欄的複製按鈕，會複製 `【影片標題】` 加說明欄前三個 hashtag（例如兩行：`【標題】` 與 `#標籤一 #標籤二 #標籤三`）。說明欄第一次才去抓，要等幾秒；沒有 hashtag 時只複製標題。
7. **下載封面**：滑鼠移到封面上，縮圖會反灰並出現下載符號，按一下即下載該影片**原尺寸**的封面（依序嘗試 maxres、720p、sd、hq 尺寸，用第一個存在的，舊影片可能只有較小的圖）。下載助手連線時，圖存到**影片的存放資料夾**，檔名是標題前六個字（不計標點與空白），例如「颱風假放不放.jpg」，同名時加 `_2`；只有擴充功能、下載助手沒連線時，會改存到瀏覽器的「下載」資料夾。
8. 影片預設放在「下載」資料夾下的 `YT下載`，可在「設定與工具」修改。
9. 如果顯示「下載引擎可能過舊」，按**「更新下載引擎」**。YouTube 常改版，引擎需要定期更新。（Mac 上這個按鈕會重新下載官方的 yt-dlp 並核對校驗碼，因為免解壓縮版不能自己更新。）

影片檔名規則：Windows 不允許的字元會換成 `_`；太長的標題會截短；已有同名但不同影片時，檔名後面加上 ` [影片ID]`。

## 冒煙測試（請在你自己的電腦做一次）

1. 安裝並啟動，確認狀態顯示「已啟動」，並顯示 yt-dlp 版本、沒有「找不到 ffmpeg」「找不到 JS 執行環境」的警告。
2. 貼一支**公開的短影片**按「增加」，確認出現標題和封面；選 720p，按開始下載。確認檔案出現、檔名是影片標題、可以播放。
3. 貼**兩三支公開影片**（含一個小的播放清單），確認依順序下載、每支之間有冷卻倒數、各自的欄位裡有進度。
4. 再貼同一支影片，確認顯示「重複下載」且不會下載。
5. 按「複製內文」，貼到記事本確認格式；把滑鼠移到封面按一下，確認影片資料夾出現「標題前六字.jpg」。
6. 再按一次下載，確認顯示「已下載過，略過」。貼一支私人或已刪除的影片，確認顯示明確的失敗原因，且不影響其他影片。
7. 安裝檔的各個步驟（選資料夾視窗、下載元件、測試、打開 Chrome 擴充功能頁）請在 **Windows 與 Mac 各跑一次**。安裝邏輯（`host/installer.py`）在開發環境用模擬的下載與假引擎測過（含 Mac 安裝檔整支實際執行），但 Windows 的 PowerShell 起手式、選資料夾視窗、Chrome 擴充功能頁的自動開啟，尚未在真實 Windows 與 Mac 驗證。

**尚未在真實環境驗證的部分**：真實 YouTube 的下載與冷卻、說明欄 hashtag 是否完整、各影片實際有哪種封面尺寸；網頁版在擴充功能剛安裝後免重新整理即偵測到（擴充功能重新載入後的行為在自動測試環境無法驗證）、GitHub Pages 實際網址與資料夾選擇器的限制。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 不確定哪裡有問題 | 重新執行安裝檔（它會自動檢查並修復），或在面板／網頁按「檢查環境」 |
| 狀態顯示「尚未部署」 | 先按「下載部署」並執行安裝檔，完成後再按「啟動」 |
| 狀態顯示「Chrome 拒絕連線」 | 擴充功能識別碼與安裝檔不符，請重新按「下載部署」並再執行一次安裝檔 |
| 顯示「找不到 JS 執行環境」或「引擎過舊」 | 重新執行安裝檔，或按「更新下載引擎」 |
| Mac 上出現「Python.framework 已損毀，無法打開」，或下載失敗訊息含 `Failed to load Python shared library … _MEI…` | 這是舊版安裝檔裝的單檔版 yt-dlp：每次執行都把自己解壓縮到暫存資料夾，而 Chrome 啟動的程式寫出的檔案會被 macOS 標成「從網路下載」而擋下。請把擴充功能更新到最新版（0.2.3 以上）後重新執行安裝檔，或在面板按「更新下載引擎」，兩者都會改裝免解壓縮版。警告視窗請按「取消」，不要按「丟到垃圾桶」 |
| 顯示「YouTube 要求登入或驗證」 | 這是 YouTube 對該網路的限制。請改用住宅或公司網路，不要用雲端或 VPN |
| Windows 安裝時 yt-dlp 無法執行 | 可能缺少 Visual C++ 執行階段，或被防毒軟體攔截 |
| 公司電腦無法安裝 | IT 可能限制了開發人員模式擴充功能、腳本執行或 Native Messaging，需請 IT 協助 |
| 更新後下載助手無法啟動 | 把 `<安裝目錄>/backup/host/` 裡的檔案複製回 `<安裝目錄>/host/`（只保留上一版的備份）。不要重新執行安裝檔：安裝檔隨擴充功能一起更新，會裝回同一份有問題的版本；要退回舊版請改用上一版的 main.zip |
| 檢查更新顯示「GitHub 暫時限制查詢次數」 | 同一個網路一小時內查詢太多次，稍後再試即可 |
| 檢查更新顯示「GitHub 拒絕了查詢（HTTP 403）」 | 公司網路的代理或防火牆擋下了 api.github.com，請 IT 放行 `api.github.com` 與 `raw.githubusercontent.com` |
| 檢查更新顯示「尚未發佈：找不到 main 分支」 | 維護者還沒把程式碼併入 `main` |
| 更新時顯示「這個資料夾不是目前載入的擴充功能資料夾」 | 你可能解壓縮了多份。到 `chrome://extensions` 找到這個擴充功能，看「載入位置」，再選那個資料夾（面板已自動忘記先前選的資料夾） |
| 網頁版一直顯示「還沒偵測到擴充功能」 | 先完成步驟 1～3（執行安裝檔、載入擴充功能）並確認擴充功能已啟用；剛裝好時網頁通常會自己偵測到，若 10 秒後仍沒有，重新整理網頁；擴充功能被重新載入後也請重新整理網頁 |
| 網頁版顯示「與擴充功能的連線中斷」 | 擴充功能被停用、重新載入或移除了。到 `chrome://extensions` 確認它已啟用；恢復後網頁會自己解鎖，不行再重新整理。連線中斷期間新增與清單都是鎖住的 |
| 網頁版顯示「與下載助手的連線中斷」 | 下載助手被關掉了，網頁會自動嘗試重新連線；如果顯示「啟動後馬上又關閉了」，代表自動重試 5 次都失敗，請重新執行安裝檔（它會自動檢查並修復），再按設定流程最後一步的「啟動」重試 |
| 顯示「下載助手的版本太舊」，「開始全部下載」按不了 | 下載助手比擴充功能舊。到側邊面板的「版本與更新」按「更新」，完成後會自動重新連線 |
| 按「下載安裝檔」後 Chrome 的下載記錄顯示失敗（檢查網際網路連線） | 這是舊版擴充功能的問題，已修正（把擴充功能更新到最新版即可）。如果仍然失敗，網頁會顯示 Chrome 回報的原因；若顯示「找不到安裝檔」，代表部署出來的資料夾缺檔，請到網頁版重新下載安裝檔或更新擴充功能 |
| 封面存到「下載」資料夾，不在影片旁邊 | 下載助手當時沒連線，或還是舊版；連線並更新下載助手後，再按一次封面即可 |
| 封面顯示「找不到封面圖片」 | 這支影片沒有任何尺寸的公開封面圖片，或暫時連不上 YouTube 圖片伺服器 |
| 清單裡有一欄顯示「重複下載」 | 清單裡已有影片 ID 或標題相同的影片，這一欄不會下載；不需要的話按 X 移除 |
| 選擇資料夾時被 Chrome 拒絕 | 不要選磁碟根目錄或「下載」「文件」「桌面」資料夾本身，請選擴充功能所在的 `extension` 那一層 |

## 維護者：發版

更新會追蹤 GitHub 上的 `main` 分支（與圖片套版產生器相同）。修改都先記錄在功能分支，不會影響同事；確認沒問題、併入 `main` 後，同事才會收到更新。每次要發版時：

1. 同步更新 `extension/manifest.json` 的 `version` 與 `host/version.py` 的 `VERSION`，兩者必須相同（測試強制）；**不要動 `manifest.json` 的 `key`**，否則擴充功能識別碼改變，更新會被拒絕。
2. 跑完測試：`python -m pytest`，並執行 `python build.py` 重新產生安裝檔、把 `extension/installers/` 一併提交。
3. 確定可以發佈後，把功能分支併入 `main`（在 GitHub 開 Pull Request 並合併，或 `git push origin <commit>:main`）。
4. 同事的擴充功能最多 6 小時內會發現新版本（或按「檢查更新」立即檢查）。

**網頁版**放在 GitHub Pages：到 repo 的 Settings → Pages，來源選 `main` 分支、根目錄（只需設定一次）。網址是 `https://unnn3ing-oss.github.io/videodownload/`；網頁與擴充功能只認這個網址，改了網址要同步改 `extension/lib/constants.js` 的 `WEB_ORIGIN`、`WEB_PATH` 與 `manifest.json`。

**安全提醒**：這套更新沒有數位簽章，信任來源就是 `main` 分支本身；能推送到該分支的人，就能影響所有同事的電腦。請對 `main` 分支開啟 GitHub 分支保護（限制誰能推送），並對所有有推送權限的 GitHub 帳號啟用雙重驗證。

## 開發

```bash
pip install -r requirements-dev.txt
python -m pytest                          # host 與建置腳本測試
node --test extension/tests/*.test.mjs    # 擴充功能純邏輯測試（含下載安裝檔、連線提示與自動連線）
npm i --no-save playwright-core@1.56.1    # e2e 需要（Chromium 位置可用 PW_CHROMIUM 指定）
node extension/tests/e2e/update.e2e.mjs     # 自我更新的端對端測試（假 GitHub、假資料夾）；環境變數同上
node extension/tests/e2e/queue.e2e.mjs      # 背景程式的清單（增加、重複、依序下載與冷卻、複製內文、封面、網頁來源限制）
node extension/tests/e2e/web.e2e.mjs        # 網頁版（以 route 模擬 GitHub Pages）：沒有擴充功能時的部署、自動偵測與連線、與側邊面板同一份清單
node extension/tests/e2e/webupdate.e2e.mjs  # 網頁版的「檢查更新／更新到最新版」（假 GitHub、安裝檔記錄的資料夾、竄改被擋下、資料夾不明時的說明）
node extension/tests/e2e/oldhost.e2e.mjs    # 連到舊版（0.1.0）下載助手時：兩個畫面的提示、停用開始、複製內文的說明
node extension/tests/e2e/sidepanel.e2e.mjs  # 無頭 Chromium 端對端測試（假引擎）；結束碼 2 代表無法啟動瀏覽器；設 E2E_SHOTS=資料夾 會順便截圖，E2E_SCHEME=dark 測深色模式
node tools/make-icons.mjs                 # 改了 extension/icons/icon.svg（網頁版與擴充功能共用的圖示）後，重新產生 PNG 圖示
python build.py                           # 修改 host 程式碼後重新產生安裝檔，並提交 extension/installers/
```

- `host/`：Native Messaging 下載助手（只用 Python 標準函式庫）。
- `extension/`：Chrome 擴充功能（Manifest V3）；`lib/queue.js` 是清單的純函式，`lib/queue-controller.js` 負責與下載助手往來，`bridge.js` 是網頁版的內容腳本。
- `index.html`、`web/`：網頁版（GitHub Pages），共用 `extension/lib/` 的清單繪製與部署程式。
- `build.py`、`installers/templates/`：產生單檔安裝檔，內嵌 host 程式碼。測試會檢查已提交的安裝檔與最新程式碼一致。
- `docs/superpowers/`：設計文件與實作計畫。
