# 批量下載清單與網頁版 實作計畫

> **給執行的代理：** 必要子技能：使用 superpowers:subagent-driven-development（建議）或 superpowers:executing-plans 逐項執行本計畫。步驟使用核取方塊（`- [ ]`）追蹤。

**目標：** 把「貼網址 → 預覽 → 開始下載」改成「增加 → 排隊 → 依序下載（含冷卻）」的批量清單，每列有標題、封面、X、複製內文、下載封面、重複標示與列內進度；側邊面板與 GitHub Pages 網頁版共用同一份清單。

**架構：** 擴充功能的背景程式保管清單（純函式 `queue.js` ＋ 接線層 `queue-controller.js`，持久化於 `chrome.storage.local`），本機小程式負責依序下載與冷卻（新增 `enqueue`／`remove`／`meta`／`save_cover`）。側邊面板與網頁版只是兩個畫面（共用 `queue-view.js` 繪製清單列）；網頁透過內容腳本 `bridge.js` 與背景程式溝通，背景程式以白名單過濾。

**技術：** Chrome MV3（背景 service worker、內容腳本、`chrome.scripting`、`chrome.downloads`、Native Messaging）、純 ES modules（node `--test`）、Python 標準函式庫（pytest）、Playwright（無頭 Chromium，`/opt/pw-browsers/chromium`，`playwright-core@1.56.1`）。

**規格：** `docs/superpowers/specs/2026-10-05-web-queue-design.md`（以下簡稱「規格」；與本計畫衝突時以規格為準）

## 全域限制

每個任務都隱含包含本節。

- 介面文案一律繁體中文（台灣用語）。標題、說明、錯誤原因等來自 YouTube 或本機小程式的文字都是**不可信的**：畫面一律用 `textContent`／`replaceChildren` 顯示，不得用 `innerHTML` 拼接。
- Chrome 最低版本 114（`manifest.json` 的 `minimum_chrome_version`）；本機小程式只用 Python 標準函式庫。
- **不動** `manifest.json` 的 `key`。擴充功能與本機小程式版本同為 **`0.2.0`**（`extension/manifest.json` 的 `version` 與 `host/version.py` 的 `VERSION`，既有測試強制兩者相同）。
- 只要修改 `host/*.py`，就要執行 `python build.py` 並提交 `extension/installers/`（既有測試 `test_committed_installers_are_current` 強制）。
- 設定值：`quality` ∈ {720, 1080}（預設 1080）；`cooldownSec` 3–60（預設 10）；`limit` 1–1000（預設 50）；清單上限 `MAX_ITEMS = 500`；本機小程式 `download` 的 `cooldownSec` 接受 0–300，缺省 2（相容舊呼叫端）。
- 封面：嘗試順序 `maxresdefault`、`hq720`、`sddefault`、`hqdefault`（網址 `https://i.ytimg.com/vi/<id>/<name>.jpg`），圖片上限 `8 * 1024 * 1024` 位元組，檔頭須為 JPEG（`FF D8 FF`）。
- 封面檔名：標題去掉所有 Unicode 類別 P、S、Z、C 的字元後取前 6 個字元；去完為空則用影片 ID；再套用 `sanitize_filename`；副檔名 `.jpg`。
- 重複判定：影片 ID 相同，或標題相同（NFKC 正規化、去頭尾空白、不分大小寫）；清單中最早者正常，其後者 `dupOf = 最早者的 uid`。
- hashtag：說明欄中依出現順序取前 3 個不重複的 `#詞`（中英文數字底線）；網址中的 `#` 片段不算；複製格式 `【標題】` 換行 `#一 #二 #三`，無 hashtag 時只有第一行。
- 網頁來源：`https://unnn3ing-oss.github.io/videodownload/`；擴充功能只信任此來源的內容腳本訊息，且只接受 `WEB_ALLOWED` 白名單。`update_*` 只限側邊面板。
- 版本控制：只在功能分支 `claude/youtube-video-downloader-4gvj18` 提交與推送；**不要**合併到 `main`、不要建立 `release`、不要開 PR、不要啟用 GitHub Pages（由使用者決定）。提交訊息結尾加：`Co-Authored-By: Claude <noreply@anthropic.com>` 與 `Claude-Session: https://claude.ai/code/session_01G1BfyDQfWQWNDybUp41ZB9`（不寫模型名稱）。
- 既有測試（pytest、`node --test extension/tests/*.test.mjs`、`sidepanel.e2e.mjs`、`update.e2e.mjs`）在每個任務結束時都必須通過；Task 9 之後 `sidepanel.e2e.mjs` 以新介面改寫。

## 審查重點

最容易出事、但各任務的一般測試未必涵蓋的情況（每一條都在擁有該程式碼的任務裡有對應測試）：

1. **惡意或特殊標題／說明欄**：含 HTML（`<img src=x onerror=…>`）、換行、很長、表情符號的標題。預期：只當文字顯示、不執行；複製內文的標題行永遠是單行。→ Task 4（`buildCopyText`）、Task 9（e2e）
2. **下載途中本機小程式斷線或重啟**：預期 `running` 變回 false、`downloading` 退回 `waiting`、冷卻清除，畫面不卡在「下載中」，可重新開始。→ Task 5（`hostLost`）、Task 6
3. **兩個畫面同時操作同一份清單**（面板與網頁同時按開始、同時刪除同一列）：預期狀態一致、不重複送出下載。→ Task 6（`start` 冪等、`syncRun`）、Task 11
4. **快速連續操作**：增加後立刻刪除、刪除正在下載或正在冷卻的那一支、同一網址連貼、達到 500 列上限、最早的重複者被刪除。預期：不當機、不遺漏、重複標示即時重算。→ Task 3、5、6
5. **偽造或越權的網頁訊息**：非白名單類型、非 Pages 來源的分頁、網頁送出 `update_*` 或未知欄位。預期：一律拒絕，不影響清單。→ Task 7
